Programmering med KI

Publisert 18. desember 2024

En av styrkene til kunstig intelligens er hvordan man kan bruke det til programmering. Men å slippe elevene løs på en "programmer dette" har vist seg i flere tilfeller å ikke fungere så bra. Her kommer en rekke tips og forslag til undervisningsaktiviteter.

PRIMM eller MPRIM?

Et nyttig verktøy når det kommer til undervisning i programmering er å utforme oppgaver etter PRIMM-modellen (Sentance et al., 2017, 2019):

Predict - Hva kommer til å skje når jeg kjører denne koden?

Run - Kjør koden. Hva skjer?

Investigate - Prøv å finn ut hva som skjedde.

Modify - Endre koden og se hva som skjer.

Make - Lag ny kode basert på den forrige for å løse et liknede problem.

En mulighet, foreslått av Andreas Haraldsrud, som oppstår med KI er at man kan snu dette akronymet på hodet, MPRIM, og få elevene til å skape kode først, før de setter i gang å predikere.

Tips og triks til bruk av KI i kode

  • Ofte kan KI-generert kode bli litt omfattende og bruke pakker som er utenfor det man venter at elevene skal kunne bruke. Si derfor fra: bruk kun disse pakkene: matplotllib og numpy, for eksempel.
  • Når det kommer feilmeldinger, be elevene om å lime feilmeldingene inn i språkmodellen, sammen med koden sin, for å få en forklaring på hva som har gått galt.
  • Dersom elevene får kode de ikke forstår, få de til å be språkmodellen om å skrive koden på nytt, men uten det de ikke forstod.

One of the strengths of artificial intelligence is how it can be used for programming. But simply turning students loose on a "program this" prompt has, in several cases, turned out not to work very well. Here are a number of tips and suggestions for teaching activities.

PRIMM or MPRIM?

A useful tool when it comes to teaching programming is to design tasks after the PRIMM model (Sentance et al., 2017, 2019):

Predict - What will happen when I run this code?

Run - Run the code. What happens?

Investigate - Try to find out what happened.

Modify - Change the code and see what happens.

Make - Write new code based on the previous one to solve a similar problem.

One possibility that arises with AI, suggested by Andreas Haraldsrud, is to flip this acronym on its head, MPRIM, and have students create code first, before they start predicting.

Tips and tricks for using AI in code

  • AI-generated code can often become a bit elaborate and use packages beyond what you'd expect students to know. So specify: use only these packages, for example matplotlib and numpy.
  • When error messages show up, have the students paste the error messages into the language model together with their code, to get an explanation of what went wrong.
  • If students end up with code they don't understand, have them ask the language model to rewrite the code without the parts they didn't understand.
